# 02. 编译流程

本篇描述编译器各阶段的输入输出与实现要点。

## ① parse：解析

使用 TypeScript Compiler API 解析 `.ets` 文件。装饰器、`struct` 等 ArkUI 语法要点处理：

- `struct X { ... }`：预处理阶段文本级替换为 `class X { ... }`（保留 sourcemap 位置映射），使 TS 解析器可直接消费。
- 装饰器（`@Entry`/`@Component`/`@State` 等）：TS 解析器原生支持装饰器语法，无需特殊处理。
- 链式 UI 描述（`Text('a').fontSize(20)`）：本质就是函数调用链，AST 中为 `CallExpression` 嵌套。
- 尾随子节点块之后的续链（如 `Column(...) { ... }` 换行后接 `.width('100%')`）不是合法 TS：预处理第二趟在这类行首 `.标识符` 前插入哨兵标记使其可解析，analyze 阶段识别标记并把链式调用挂回前一组件节点；两趟预处理的列偏移合并进同一张位置映射表，诊断行列始终回溯到原始源码。

```ts
// 伪代码
function parse(filePath: string): ts.SourceFile {
  const source = preprocessStruct(readFile(filePath));   // struct → class
  return ts.createSourceFile(filePath, source, ts.ScriptTarget.ES2020, true);
}
```

## ② analyze：语义分析

遍历 AST，为每个组件提取结构化模型：

```ts
interface ComponentModel {
  name: string;                    // struct 名
  isEntry: boolean;                // @Entry 标记
  states: StateField[];            // @State 字段（名称、类型、初始值、@Watch 回调）
  props: PropField[];              // @Prop / @Link / 普通成员
  lifecycle: LifecycleHooks;       // aboutToAppear 等
  methods: MethodDecl[];           // 普通方法（事件处理等）
  buildTree: UINode;               // build() 的 UI 结构树
  builders: Record<string, UINode>; // @Builder 方法
}

interface UINode {
  component: string;               // 'Column' | 'Text' | 'Button' | ...
  params: Expression[];            // 构造参数 { space: 12 }、'文本'
  children: UINode[];              // 嵌套子节点（含 if / ForEach 控制节点）
  styleCalls: StyleCall[];         // .fontSize(20) 等链式调用
  eventCalls: EventCall[];         // .onClick(() => {...})
}
```

分析期的关键工作：

- **装饰器识别**：建立装饰器白名单表，未识别的装饰器报错（见 08 篇）。
- **控制流归一**：`build()` 中的 `if/else`、`ForEach` 转为特殊的控制节点（`IfNode` / `ForEachNode`），供模板生成阶段翻译为 `wx:if` / `wx:for`。
- **表达式分类**：区分"纯静态表达式"（可编译期求值，如 `.fontSize(20)`）与"依赖状态表达式"（如 `` `count=${this.count}` ``），前者进 WXSS/静态属性，后者进 WXML `{{}}` 绑定。

## ③ IR：中间表示

`ComponentModel` 即核心 IR。IR 与两端语法解耦：

- 不引用任何 `ts.Node`，所有表达式已序列化为可求值的描述（`{ kind: 'static', value: 20 }` 或 `{ kind: 'binding', path: 'count', template: 'count=${0}' }`）。
- 附加目标无关的元信息：每个 UI 节点分配稳定 id（`n0`, `n1`…），用于样式类名与事件名生成。

## ④ transform：四条转换链

```text
ComponentModel
 ├─ buildTree ──→ WXML 生成器       组件映射表 + 控制流翻译（03 篇）
 ├─ styleCalls ──→ WXSS 生成器      白名单属性 + 类名收集（04 篇）
 ├─ states/props → JS 生成器        data/properties/桥接方法（05 篇）
 └─ events ──────→ 事件表           回调体抽取为方法，模板侧 bindtap
```

事件处理示例：

```ts
// 源码
Button('确定').onClick(() => { this.submit(this.form.id); })
```

转换：

```html
<!-- wxml：事件名为节点 id 派生 -->
<view class="arkmp-btn" bindtap="__n7_click">确定</view>
```

```js
// js：回调体原样抽取为方法
__n7_click() {
  this.submit(this.form.id);
}
```

回调体中的 `this.xxx = ...` 状态赋值由 ⑤ 阶段的赋值改写器处理（05 篇）。

## ⑤ emit：代码生成

输出四件套 + json 配置：

| 产物 | 生成来源 |
| --- | --- |
| `.wxml` | buildTree（含静态属性与 `{{}}` 绑定） |
| `.wxss` | 静态样式类 + runtime 基础类（`arkmp-col` 等） |
| `.js` | `Page()`/`Component()` 调用：data、properties、methods、生命周期 |
| `.json` | 页面配置（navigationBarTitleText 等，来自 `@Entry({...})` 参数） |

生成原则：

- **可读性优先**：缩进、命名接近手写风格；生成代码带头部注释 `// Generated by ArkMP, do not edit`。
- **sourcemap**：js 产物生成 sourcemap，支持在微信开发者工具中回溯到 `.ets` 源码。

## ⑥ 增量编译与 watch

- 以文件为单位缓存 `ComponentModel` 的哈希，仅重编译变更文件。
- 组件依赖图：被 `@Builder` 或自定义组件引用的文件变更时级联重建引用方。
- watch 模式输出直接写入小程序工程目录，配合微信开发者工具的"文件监听自动编译"实现保存即预览。

## 错误诊断

- 每个转换阶段产出结构化诊断（文件、行列、错误码、修复建议），统一格式：

```text
arkmp E1023 [pages/Index.ets:24:9]
  不支持的组件：Video（小程序端请使用 ArkMP 的 <Video> 适配组件）
  帮助：见 docs/arkui-miniprogram/03-component-mapping.md#视频
```

- 诊断分级：`error`（阻断构建）/ `warning`（降级输出，如样式属性不支持时转为内联注释）。
